
# PyGDS 与 CPython 差异清单

本文件记录 PyGDS 与 CPython 的行为差异与功能缺失，按成因分为三系：语言核心对齐缺口（Issue）、有意替代模型（Design）、宿主平台限制（Platform），含未处理与已处理条目，供版本规划与交接使用。该文件并非 GitHub 仓库中 Issues 页面的迁移版本，但可以在文件中引用 Issues 页面的相关链接。Issue 一词在本文件中特指语言核心层的对齐缺口分类，与 GitHub Issues 无关。本文件遵守 [代码与文档规范](./standards.md#代码与文档规范)

三系分类以「差异由谁决定」为判据：

- **Issue（I 编号，语言核心层）**：数据模型、求值顺序、内建类型对纯值的行为、异常类层级等语言核心的对齐缺口。对齐要求：必须对齐 CPython——这是用户可以放心依赖的部分，双端差分测试是它的回归安全网。按优先级（Priority） 0 / 1 / 2 分级：
  - **I0**：静默给出错误结果（数值/输出错误但不报错）
  - **I1**：明确报错或功能缺失（可预期、不会静默错值）
  - **I2**：行为的边缘差异（错误类型/文案不同，但双方都报错或都成功）
- **Design（D 编号，设计层）**：有意的替代模型与既定不对齐（如自有 PRNG、稳定身份哈希、步数安全阀）。对齐要求：有意为之、文档化、尽量显式报错而非静默错值，不追求与 CPython 一致
- **Platform（P 编号，平台层）**：文件路径、编码、libm 舍入、精度边界、引擎硬上限等宿主平台决定的差异。对齐要求：按宿主平台如实差异并文档化——CPython 自己跨平台也这样。宿主升级后应复核条目是否解除

三系编号各自独立计数，由 `<分类字母>[<二级分类><->]<序号>` 组成，具体如下：

- Issue：`I<Priority>-<序号>`，例如 `I0-1` 代表 Issue 内，P0（特指 Priority 0 而非 Platform 0）级问题的第一个问题
- Design：`D<序号>`，例如 `D1` 代表 Design 内第一个条目
- Platform：`P<序号>`，例如 `P1` 代表 Platform 内第一个条目

即使该条目已经被处理，其序号也不会回收使用。Issue 条目转入 Design / Platform 时原编号退役，新条目不得占用
