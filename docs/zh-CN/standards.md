
# 代码与文档规范

## 代码编写

### 不允许行内多语句

不允许出现行内多语句

```gdscript
# 错误示例
if true: var a = 10; var b = 20;

# 应当改为
if true:
  var a = 10
  var b = 20
```

### 符号与标点规范

1. 代码以及注释内不允许出现分号（排除字符串字面量、URL、正则等实际工作的内容）
2. 注释内的中文符号仅在作为被描述内容、避免歧义、引用原文或正式名称时允许（例如注释 `# 替换所有的 "【】" 符号` 中的中文符号起说明作用，允许存在）
3. 英文逗号、冒号、感叹号、问号等标点后，如果后面还有正文，则加一个空格

```gdscript
# 错误示例: 携带分号
# 这是一条注释; 这也是一条注释

# 正确示例
# 这是一条注释
# 这也是一条注释

# 错误示例: 携带中文符号
# 这是一条注释，这也是一条注释

# 正确示例
# 这是一条注释, 这也是一条注释

# 错误示例: 英文符号后无空格
# 这是一条注释,这也是一条注释

# 正确示例
# 这是一条注释, 这也是一条注释
```

### 文档注释合理使用 `BBCode`

文档注释应该在非尾行后添加 `[br]` 符号（Godot 文档注释不会自动保留软换行），此处认为 `[code]` 符号可能会影响阅读，故可不添加

```gdscript
# 错误示例: 无符号
## 这是一条文档注释
## 这也是一条文档注释

# 错误示例: 尾随符号
## 这是一条文档注释 [br]

# 正确示例
## 这是一条文档注释 [br]
## 这也是一条文档注释
```

### 外部引用

注释内不应该出现不必要的外部引用，或缺少必要的外部引用，必要场景包括：

1. 关联已知问题、issue、PR
2. 关联设计文档、协议、标准
3. 解释无法在注释中展开的背景
4. 标记临时绕过方案和移除条件

```gdscript
# 错误示例: 出现不必要的外部引用
# 该问题 (P0-1) 已在 v1.0.0 版本被修复, 方法已正常运行

# 正确示例: 编写该代码的作用, 或在修复后直接省略问题编号与被修复时的版本信息
# ... (方法描述)

# 错误示例: 缺少必要的外部引用
# 该方法存在异常

# 正确示例
# 该方法存在异常, 详见已知问题清单 (编号 P0-1)
```

## 文档编写

### 文档符号

文档应该使用对应语言的符号，并且英文符号之后需要跟随空格。中文文档中，一段话的句尾允许不出现句号，在表格内等区域建议不出现句尾句号，英文文档应该出现句号

```markdown
这是一段中文文档，描述了一段代码的作用。这段代码用途很多，分别是：用途 A、用途 B 以及用途 C

This is a Chinese document that describes the function of a piece of code. This code has many uses, including: use A, use B, and use C.
```

### 代码块规范

代码块内的文本应该遵循 [代码编写](#代码编写) 内的规范

## 特殊文档

### 提交信息

Git 提交信息应该满足以下规则

1. 第一行是主题，尽量不超过 50 字符，第二行空行，正文每行不超过 72 字符
2. 代码部分应该添加 markdown 行内代码块符号
3. 尽可能满足 Commit message 规范

### Changelog

`CHANGELOG.md` 应该满足以下规则

1. 开发过程中，把变更写入 `## [Unreleased]` 下对应分类
2. 发布时，将 `Unreleased` 改成具体版本号和日期（例如 `## [1.2.0] - 2024-06-01`），随后在顶部重新创建一个空的 `## [Unreleased]`
3. 尽可能满足 Keep a Changelog 与 Semantic Versioning 规范（版本见 `CHANGELOG.md` 文档）

### 已知问题清单

文档 [已知问题清单](issues.md) 应该满足以下规则

***问题表格汇总***

其规则已写明在章节头部（详见 [问题表格汇总](./issues.md#问题表格汇总)），以下是表格的一行示例

```markdown
| 编号 | 状态 | 发现时间 | 发现版本 | 问题简要描述 |
| :--- | :--- | :--- | :--- | :--- |
| [P0-0](#p0-0-问题示例) | 不修复 | 2026-09-29 | `v0.6.0-alpha.1` | 问题简要描述 |
```

***问题章节编写***

问题章节编写应该按照以下样例编写

````markdown
### P0-0 问题示例

***问题简要描述***

（示例二）该问题发现于 2026-09-29，`v0.6.0-alpha.1` 版本，来自 [GitHub Issues](https://github.com/CharaCat233/PyGDS/issues) 页面，某个函数存在严重的副作用，并且无警告或报错

***问题状态***

（示例一）由于 Godot 平台限制，该问题修复难度极大，暂时不修复

（示例二）该问题已于 2026-09-29 修复，作为 `v0.6.0-alpha.2` 版本的一项任务

***最小复现案例***

```python
# 示例 Python 代码
```

```txt
```

```txt
```

***修复记录与备注***
````
